Keeta BPO Scorecard — High-Level Overview

Target Audience: Product Managers, Directors, Stakeholders

1. High-Level System Architecture

The Keeta BPO Scorecard is a Progressive Web Application (PWA) designed to standardise how BPO vendors are audited and evaluated. It operates effectively as a "smart spreadsheet" with a powerful visual layer, currently running entirely within the user's browser.

Core Concept

Think of the application as a self-contained evaluation tool. Instead of sending data back and forth to a central server for every click, the application loads once and handles all calculations, data storage, and report generation instantly on the user's device.

Major Components

  1. Dashboard Area: Provides instant feedback on vendor performance (RAG status: Red/Amber/Green).
  2. Audit Interface: A digital form where Regional Training Managers input performance data against specific Categories and KPIs.
  3. Calculation Engine: An "invisible brain" that instantly computes complex weighted scores as data is entered.
  4. Admin/Configuration Panel: Allows authorised users to change the "Rules of the Game"—weightings, KPI definitions, and scoring targets—without needing a developer.
  5. Report Generator: Creates PDF exports and visual charts for Monthly Business Reviews (MBR).

How Data Flows

  • Configuration: The "Rules" (KPIs, Weights) are loaded.
  • User Input: The Manager selects a Vendor and Period, then enters "Actual" vs "Target" numbers.
  • Scoring: The system calculates the score in real-time (e.g., 98% Compliance = 100 Points or Fail = 0 Points).
  • Storage: Data is saved locally to the browser's secure storage.
  • Output: Dashboards update immediately; PDFs can be downloaded for email distribution.

2. Tech Stack Summary

The technology choices prioritise speed, portability, and modern user experience.

Component Technology Why it was chosen
Frontend Framework React + TypeScript The industry standard for building interactive, complex user interfaces. Ensures type safety and few bugs.
Styling Tailwind CSS Allows for a modern, clean, "SaaS-like" aesthetic that is mobile-responsive.
Charting Recharts Renders professional-grade trend lines and bar charts for the dashboards.
Application Logic Node.js (Compatible) The logic is written in JavaScript/TypeScript, making it easy to move to a backend server later if needed.
Storage (Current) Local Storage + IndexedDB No Database Required. Allows the app to work offline or without a server setup. Uses IndexedDB for large file attachments.

3. What the System Does

The Problem It Solves

Previously, audits might have been done in disparate Excel sheets, leading to version control issues, broken formulas, and inconsistent reporting. This tool standardises the source of truth.

Key Workflows

  • Audits: A user selects a vendor (e.g., "Teleperformance") and a month (e.g., "Oct 2023"). They walk through defined "Pillars" (Training, Compliance, etc.) and mark items as Done/Met or Pass/Fail.
  • Scoring Logic: The system handles the complex math. It understands that:
    • Some KPIs are Linear (85% achievement = 85 points).
    • Some are Binary (Pass/Fail = 100 or 0 points).
    • Some are Inverse (Lower attrition is better).
  • Category Weighting: If a Category is worth 20% of the total score, the system automatically scales the KPIs within it to equal that 20%.

4. What is Customizable?

The system is designed to be highly flexible via the Configuration Panel:

  • KPI Definitions: You can add, remove, or rename KPIs.
  • Weighting: You can adjust a category's importance (e.g., change "Training Delivery" from 30% to 40%). The system validates that totals equal 100%.
  • Scoring Logic: You can switch a KPI from "Standard Percentage" to "Pass/Fail" logic without writing code.
  • Vendor List: Vendors are not hardcoded; you can manage the list dynamically.

5. Integration Strategy & Missing Features

Currently, the system is Standalone. To integrate it into the corporate platform, we need to "unplug" the local storage and "plug in" a centralised database.

Critical Missing Components: Authentication

There is currently NO real sign-in or registration process. The application simulates a login with data stored in your browser.

We must implement:

  • Registration Flow: A page for new users (e.g., vendor focal points) to sign up.
  • Sign-In Validation: A backend service to verify passwords securely.
  • Access Control: Locking down editing rights so Vendors can only see their scores, while Managers can edit them.

Integration Path

  1. Frontend (Portable): The UI (React) is ready to deploy. It can be hosted on any web server, Sharepoint page, or Azure Static Web App.
  2. Data Storage (The Change Required):
    • Current: Uses User's Browser Memory.
    • Target: Needs to connect to an API (Node.js) or SharePoint Lists.
  3. Authentication: Needs integration with SSO (Single Sign-On) or Azure Active Directory for security.
