Keeta BPO Scorecard — High-Level Overview

Target Audience: Backend Developers & DevOps Engineers

1. High-Level System Architecture

The Keeta BPO Scorecard is a Progressive Web Application (PWA) designed to standardize BPO vendor audits and evaluation. The frontend is a React-based SPA that currently runs entirely client-side with browser-based storage. Backend integration is required to enable centralized data storage, multi-user access, and production deployment.

Current Architecture

The application is a client-side only implementation. All business logic, calculations, and data persistence currently execute in the browser using LocalStorage and IndexedDB. To deploy this tool on the company's internal platform, you'll need to implement backend services for authentication, data persistence, and file storage.

Major Components

  1. Dashboard Area: Provides instant feedback on vendor performance (RAG status: Red/Amber/Green).
  2. Audit Interface: A digital form where Regional Training Managers input performance data against specific Categories and KPIs.
  3. Calculation Engine: Core business logic that computes complex weighted scores in real-time. Currently executes client-side but can be migrated to backend for consistency.
  4. Admin/Configuration Panel: Allows authorised users to change the "Rules of the Game"—weightings, KPI definitions, and scoring targets—without needing a developer.
  5. Report Generator: Creates PDF exports and visual charts for Monthly Business Reviews (MBR).

How Data Flows

  • Configuration: The "Rules" (KPIs, Weights) are loaded.
  • User Input: The Manager selects a Vendor and Period, then enters "Actual" vs "Target" numbers.
  • Scoring: The system calculates the score in real-time (e.g., 98% Compliance = 100 Points or Fail = 0 Points).
  • Storage: Data is saved locally to the browser's secure storage.
  • Output: Dashboards update immediately; PDFs can be downloaded for email distribution.

3. What the System Does

The Problem It Solves

Previously, audits might have been done in disparate Excel sheets, leading to version control issues, broken formulas, and inconsistent reporting. This tool standardises the source of truth.

Key Workflows

  • Audits: A user selects a vendor (e.g., "Teleperformance") and a month (e.g., "Oct 2023"). They walk through defined "Pillars" (Training, Compliance, etc.) and mark items as Done/Met or Pass/Fail.
  • Scoring Logic: The system handles the complex math. It understands that:
    • Some KPIs are Linear (85% achievement = 85 points).
    • Some are Binary (Pass/Fail = 100 or 0 points).
    • Some are Inverse (Lower attrition is better).
  • Category Weighting: If a Category is worth 20% of the total score, the system automatically scales the KPIs within it to equal that 20%.

4. What is Customizable?

The system is designed to be highly flexible via the Configuration Panel:

  • KPI Definitions: You can add, remove, or rename KPIs.
  • Weighting: You can adjust a category's importance (e.g., change "Training Delivery" from 30% to 40%). The system validates that totals equal 100%.
  • Scoring Logic: You can switch a KPI from "Standard Percentage" to "Pass/Fail" logic without writing code.
  • Vendor List: Vendors are not hardcoded; you can manage the list dynamically.

5. Backend Requirements for Production Deployment

The current implementation is client-side only with browser-based storage. To deploy this tool on the company's internal platform with multi-user access and centralized data, the following backend infrastructure is required:

Critical Backend Components Required

1. Authentication & Authorization Service

  • User Management: Implement user registration and authentication system
  • SSO Integration: Integrate with Azure Active Directory or company SSO provider
  • Role-Based Access Control (RBAC): Implement roles (Admin, Manager, Vendor, Viewer) with granular permissions
  • Session Management: Token-based authentication (JWT) with secure refresh mechanisms

2. Database & Data Persistence

  • Primary Database: PostgreSQL, MongoDB, or SQL Server for structured audit data
  • Schema Requirements:
    • Users table (id, email, role, permissions, created_at)
    • Audits table (id, vendor_id, period, status, scores, created_by, updated_at)
    • Configurations table (scorecard_config JSON, KPI definitions, weights)
    • Vendors table (id, name, contact_info, assigned_managers)
  • File Storage: Azure Blob Storage or S3 for PDF reports and file attachments

3. RESTful API Endpoints Required

Base URL: /api/v1

  • POST /auth/login - User authentication
  • POST /auth/register - User registration (admin only)
  • GET /audits - List audits (filtered by user role)
  • POST /audits - Create new audit
  • GET /audits/:id - Get specific audit details
  • PUT /audits/:id - Update audit data
  • DELETE /audits/:id - Delete audit (admin only)
  • POST /audits/:id/finalize - Mark audit as complete
  • GET /audits/:id/pdf - Generate and download PDF report
  • POST /files/upload - Upload audit attachments
  • GET /configs - Get scorecard configurations
  • PUT /configs - Update configurations (admin only)
  • GET /vendors - List all vendors
  • POST /vendors - Create vendor (admin only)

4. Real-Time Data Synchronization (Optional)

  • WebSocket Support: For real-time audit updates when multiple users are viewing the same data
  • Technology Options: Socket.io, SignalR, or native WebSocket implementation
